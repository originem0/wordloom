## 1. 目标与约束

把已经遇见的词和表达，变成有需要时能找回、能理解、能再次使用的个人语言资源。优化的重点是减少入口与默认分析负担，补齐真实来源和个人使用记录。

本计划整合三轮调研，并采用用户最新确认的要求：

- 沿用原站视觉。复用现有浅色、Solarized 暗色、字体、按钮、卡片、词卡详情及移动导航样式，不另造配色和设计系统。
- Cards 保留独立入口与 Word Forge 功能，新增表达库不替代词卡。
- Story、Practice 等低频看图功能合并、精简为按需工具；Chunks 融入表达库，但保留已有资料与分析能力。
- 新表达库充分结合 AI 问答，支持手动收藏、对话收藏、模糊需求找回、新表达推荐及原场景回看。
- 单词、短语、句式、整句都可以收；自己的卡壳和误表达也可以成为重说练习题。
- 外置脑提供有依据的候选表达和能力记录，不宣称知道用户脑内的知识总量。
- 沿用 React / Vite / Hono / SQLite、现有 AI provider、鉴权和任务机制，不引入未要求的新依赖。

早期方案中的“仅关键词检索”“不做 AI 对话”“把 Cards 收为次级参考入口”不再作为实施约束。需要真实来源快照后，也不再硬守两张新增表的限制。

## 2. 三轮调研所得

| 调研 | 已得到的结论 | 在本计划中的落点 |
|---|---|---|
| 项目、表达困境聊天与英语笔记 | 主要困难是已遇过表达找不回、用不出。项目偏重材料与解释生成，练习回答和反馈不留存，提示曝光也没有可靠区分。现有栈可维护，没有重写依据。 | 保存原场景与原回答；区分找回、辅助应用、延迟提取和换情境复用；渐进修改。 |
| AI 表达库需求与草图评估 | 收藏和问答必须同处一个流程。模糊需求可以交给 AI，但库存原文、新推荐、能力推测不能混在一起。同一句、同一单词的不同用法要保留语境。用户明确要求原站样式和 Cards 独立保留。 | 三个主入口；场景化表达条目；合法库存 ID 回读；真实来源快照；Cards 与表达库关联。 |
| SpeakLoop 参考站点 | 原话、准确版、自然版对照；收藏题目与重说题；连语境与个人理解一起收藏；原句回想与新情境输出分开；示例、真实记录及未评分状态明确区分。 | 采用这些局部交互，不照搬课程画廊、完整阅读器、会员与大统计系统。 |

第一轮 V2、第二轮 D1 曾分别由三位子代理交叉审议并明确赞同。本整合文档加入了后续 Cards、样式约束和第三轮调研所得，不把旧投票冒充对新增内容的再次投票。

## 4. 主要用户流程

### 收藏与来源

用户可以手动提交原文，也可以在 AI 回复中选词、选句收藏。保存现成表达时只要求原文；意图、义项、语域、来源和个人理解可后补。

对话收藏自动留存当时的原问题、原回答与解释意义所需的前文。用户后续又聊了别的内容，再回头收藏旧回复，仍必须关联旧回复所在的那一轮。

收藏自己的卡壳或题目时，可以先留中文意图、场景和原始尝试，不强迫用户已经拥有满意的英文答案。原话、建议答案与目标表达分别保留。

同一句在不同情境、同一单词在不同义项下可保存为不同条目。重复时提示用户补充或保留另一用法，不按英文原文全局唯一覆盖。

收藏不会自动进入主动练习。只有用户选中的条目进入练习集合；练习前确认此处的意图或具体用法即可，不把整理表单变成收藏门槛。

### 模糊需求找回与推荐

用户直接描述想表达的意思。AI 理解意图、对象和语气，有影响选择的歧义时再澄清。

同一次回复区分三种结果：

| 结果 | 呈现要求 |
|---|---|
| 我的收藏 | 返回真实条目 ID，回读原文、来源与个人线索，说明为什么适合当前场景。 |
| 旧词卡 / 语块参考 | 明确是已有资料，不能因此声称用户学过或会用。 |
| 新推荐 | 明确为新建议，说明意思、场景或语域的改善；用户选择后才收藏。 |

更合适不等于更高级、更长或更生僻。另一种正确表达不因没有采用推荐句就被判错。

初期手选库较小，让 AI 比较完整的轻量目录：真实 ID、原文、已记录意图或义项、精简情境。不要把全部 Deep 内容或完整聊天每次塞给模型。

AI 返回 ID 后，由服务端检查它属于本次候选和当前用户可访问的库，再回读保存的原文。模型自行写出的新句子不能冒充库存原句。

当目录超过上下文预算时，不能静默截取部分条目后宣称搜索了全库。显示实际范围，用真实模糊需求评估漏召回，再决定语义候选召回的增量方案。普通关键词或扩词不能冒充已经解决任意语义找回。

无匹配只能表示这次没有找到匹配项，不能推断用户不会、从未学过或库中一定没有。

### 原场景回放与前后对照

回放直接读取来源原文，不请求 AI 重建过去。显示首次留存的原问、原答、必要前文、已知出处和时间，同时说明保存范围。

首次留存时间、原材料时间、实际第一次学到的时间是不同概念。未记录就留空；AI 摘要、模拟情境和后续改写另作标记，不覆盖原始快照。

保存素材时保证回放所需内容能持续访问，避免原故事或词卡删除导致场景一起消失。首期优先文字来源；图片等需要回放时，保留实际素材副本或受保护引用。

表达纠正沿用 SpeakLoop 可取的组织方式：保留我的原话，给出贴近原意的准确改法，再按需要给自然说法和简短理由。纠正应回应真实意思，不以长篇分析代替交流。

原场景可转为重说题，也可另给新情境。刚看完原句再尝试，属于有辅助应用，不是独立回忆。

### 外置脑与能力证据

外置脑的第一版提供一份有来源的候选草案：优先用用户已有资源组织意思，指出哪些曾有本人使用记录，哪些只是收藏，哪里补入了新表达或新用法。

收藏、本人自报理解、提示后使用、符合条件的无提示使用、换情境复用分别记录。每个能力判断都能回看相关原回答和条件，用户可以纠正模型判断。

AI 生成的草案、改写或引用，不计为用户自己的产出。库存不存在不能推出用户不会；库存存在不能推出用户会用。现阶段不输出脑内词汇总量或绝对掌握比例。

正常聊天继续内容交流。用户选择先让我尝试或我来描述时，才进入主动表达流程；不要额外要求重复点击另一种确认按钮。

## 5. 学习记录与判断规则

学习结果分开看：

- 这次是否把意思说清、英语是否可接受。
- 目标表达是否在当前语境中自然复用。

可以传意成功，同时没有复用目标表达。不要用原句字符串匹配代替判断，也不要要求强塞收藏词组。AI 评价保留引文、理由和不确定状态。

原回答先保存，再请求点评。点评可以 pending / failed / done，同一尝试 ID 上重试；失败不丢答案、不重复计次、不判答错。原始反馈与用户修正分开保留。

独立提取采用有条件的统计：

- 本次作答前没有站内目标、提示或答案曝光，并自报没有外部辅助。
- 自报查了站外笔记或获得其他帮助的尝试，标为有辅助并排除独立率。
- 外部辅助未说明时，只能称站内未记录辅助，不能确认全程独立。
- 保存并显示真实时间间隔。初期至少 24 小时是可调整的产品筛选规则，不是科学掌握线。
- 搜索结果、详情原句、提示、答案、点评改写和目标 TTS 的实际呈现均属于曝光。
- 本次作答前的条件锁入快照；提交后的点评曝光影响下一次的延迟窗口。

23:59 看答案、00:02 作答只有三分钟，不能因为跨日期就算延迟提取。即时重写也不能当作延迟提取。

用最近已记录曝光时间和尝试快照实现首期需求，不建设独立曝光事件平台。展示次数、分子、分母和条件；未作答、未评分、失败和示例数据分别处理。

首期文本尝试只能支持书面提取与迁移判断。打字耗时不是口语反应速度，四道题或一段文字也不能确定完整词汇能力。

## 6. 数据与技术边界

先围绕三个核心实体设计，不用固定表数替代关系正确性：

| 实体 | 保存什么 | 关键边界 |
|---|---|---|
| expressions | 表达条目或重说题、原文 / 意图 / 具体用法、个人注释、练习选择、简单下次练习日期、最近已记录曝光时间、可选旧卡关联。 | 普通表达与卡壳题的必填内容不同；独立 ID，不以词形全局唯一。 |
| source_snapshots | 收藏时实际保存的原问、原答、必要前文或素材原文、出处位置、采集时间和范围。 | 原始内容不可被新解释覆盖，多条表达可以共用一个真实来源。 |
| attempts | 本人原产出、任务类型、场景与目标快照、辅助与时间条件、反馈状态及修正。 | 历史不随条目或旧卡编辑而改变；点评失败可沿同 ID 重试。 |

旧 cards、chunks、stories、practices 不合并重建。可选关联删除时置空，但来源与尝试快照仍能独立阅读。批量旧库存默认只是参考，不自动转为个人知识或复习任务。

新增表前取得一致性数据库备份，在副本上验证迁移、回滚和历史读取。涉及素材移动或清理时另外保护实际素材，不直接覆盖现有数据库。

可复用 provider 通信、超时取消、重试与 fallback、并发限制、JSON 校验和安全文本渲染。原生问答需要新的任务入口，不能把 Chunk 分析 prompt 当聊天接口。现有代码提供通信基础，尚不代表已有完整会话系统。

当前会话保留实际短期上下文，收藏时固化来源。每次发给模型的上下文可以有界；不能用模型摘要替换保存的原文。首期不默认永久归档所有聊天，也不承诺恢复关页前未保存的会话。

新增个人对话、来源、能力记录、导出与关联任务均显式使用现有管理员鉴权。GET 不能因全局写保护而误当私有；新个人内容不能混进公开 Cards 列表或其缓存。如果复用 Job，私有任务的详情与取消也要鉴权。

附图点评依据实际图像或用户确认过的事实。旧 Practice grader 主要读取 visualPrompt，不能直接当作任意上传图片的真相。模型无法可靠识图时，缩小为语言点评并说明范围。

## 7. SpeakLoop 的取舍

| 可借鉴的设计 | WordLoom 的改法 |
|---|---|
| 我的原话、说准确、说地道对照 | 在同一回复中保留原话和少量修改依据，不让纠正覆盖来源。 |
| 收藏题目、重说练习题 | 把自己的表达卡壳和误表达留下，建立下次的真实触发情境。 |
| 收藏表达同时收藏语境与我的理解 | 保存原问原答与个人使用线索，支持回放和再说一次。 |
| 原句回想、输出复习、新话题表达分开 | 首期优先意图回想与换情境输出，按需展开提示，不复制全部学习模式。 |
| 真实、示例、未评分记录明确区分 | 能力建议引用真实记录，缺数据就保留未知，不补造分数。 |
| 在词或句子旁继续追问、收藏 | Cards 与 AI 回复都可带所选内容和上下文进入问答与收藏。 |

不能直接照搬的是回答前展示推荐表达、再用“用到回答”插入目标句后，却仍按独立提取理解这轮输出。它适合辅助训练；本系统必须记录提示条件。

参考站的公开流程主要从素材发起学习。WordLoom 还要补齐从模糊表达需求反向找回资源的路径，不能假设参考站已经解决这一需求。

## 8. 实施顺序与阶段验收

|---|---|---|

| P2：AI 问答与找回 | 正常内容对话、模糊需求理解、个人库与旧资料匹配、新推荐、前后对照。 | 使用真实模型和库存；原文回读合法 ID；三种来源标清；超预算不伪报全库检索；正常聊天不强制测验。 |

用约 20–30 条本人挑选的表达和卡壳情境试跑两周。它们是验证样本，不是每日配额；两周是产品观察窗口，不承诺某个学习提升比例。

用一组可追溯的真实模糊需求验证召回，包含同义改述、单词义项歧义、原库无匹配、只有旧参考库存及新推荐等情况。保留固定目标样本与可审查情境，不把题目变难或提示减少造成的变化直接解释为进步。

必要的代码去冗余放在核心链路跑通之后：提取 Gemini / OpenAI 重复的任务级解析与校验；测量列表是否携带不必要的 Deep 大字段；按生产导入确认旧实现再清理。PrototypeWordCard 和 Schema*Proto 正在生产使用，不能按名字当废代码删掉。

## 9. 第一期不做

- 重写技术栈，合并全库为通用学习对象，搭建知识图谱、独立向量数据库或脑模拟框架。
- 全量扫描英语笔记、自动把库存排入复习、Obsidian 全库双向同步。
- 课程画廊、完整阅读器、会员体系、社区与多用户权限系统。
- 没有依据的掌握分、脑内词汇总量、口语能力承诺，或把示例和模型推测计入真实进度。
- 为保存一次来源建立全会话归档平台。后续若明确需要完整聊天恢复，再单独设计会话持久化。
