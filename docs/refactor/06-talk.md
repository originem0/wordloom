## 2. 用代码固化的规则

1. **遮着的英文不发给模型。** 索引的英文列清空，所有提示句也过遮挡，包括另一条提示句引用的目标；历史、批注输入和回顾提示同样处理。
2. **`____`。** 模型写的任何一段话（回复、改写、理由），以及回看旧对话时的每一个字段（包括用户自己当时的话），凡是说出了「此刻遮着、这次响应又没亮出来的条目」的目标，那几个词换成 `____`。一个函数，所有出口都过它。发给模型的历史同样处理。
3. **纠正必须引用原话。** `rewrites[].from` 不是用户这句话的逐字子串就丢掉。至多 3 条。
4. **推荐的表达必须真的出现过。** `fresh[].text` 得是回复或 `fix` 的逐字子串；服务端按句子切分，找出它所在的那一句，收下时原文是那一句、焦点是这个表达。找不到就丢掉。至多 2 条。推荐的表达本身是库里某条的目标：不算新的，那一条进命中（旧规则，保留）。
5. **`fix` 和原话一样就不给。** 归一化后相同记成 `null`。
6. **命中只认发出去的 id**，至多 5 个，原文取自数据库。批注从当前消息的相关候选里检索，索引上限 12,000 字符。流式回复只接收消息、历史和可选回顾提示。
7. **用户写的是不是英文由代码判**：消息里没有汉字就是英文。写英文的那一轮，命中直接亮出来，`looked_up` 行 `cue` 留空（算看过答案）；写中文的那一轮，遮着的命中照旧遮着，可以先试写或看答案。
8. **历史由服务端从库里取**（开头一轮加最近 11 轮），不由页面带上来。
9. **完整回复先保存，批注随后更新。** 普通和流式请求共用提交路径。流式先显示草稿，完整回复按消息 ID 去重并保存。批注和它的 `looked_up` 在一个事务中更新，之后才发 `done`。回复失败不写对话；批注失败保留回复、带 `coachingFailure`，可以在同一轮重试，命中不重复记。
10. **流式不能从边界漏答案。** 留住一个最长目标所需的尾部词，先找完整命中再切输出；长空白、弯引号、重叠目标和未完整的单词都保留到可安全输出。所有文字输出和当前可见的命中字段都过同一个遮挡函数。
11. **去重。** 归一化相同的改写只留第一条；整句已经表达的改法不另列；推荐不重复改法，同一焦点只推荐一次。
12. **回顾由代码选择。** 第三轮起每四轮至多一次，用 `试一条` 的到期、容量和毕业规则。情景必须逐字出现在回复、未透露目标，而且同一响应没有亮出该目标。下一条英文复用现有判定，中文继续不计失败；尝试先于 `looked_up`，同一轮用来源关联防重。判错仍可以推翻。

## 3. 数据

新表 `talk_turns`（迁移 0012，第三张新表）：`id`、`thread`、`said`、`reply`、`notes`、`created_at`。`notes` 保存通过引用校验的 `fix`、`rewrites`、`fresh`、命中 id、检索数量，以及 `coachingPending` / `coachingFailure`、回顾候选、`review`、`reviewAttempt`。`____` 在读时按当前遮挡状态现算。回顾尝试的来源为 `chat`，定位为 `talk:<turnId>`，不另建表。

和表达一样是私人数据：挂在 `requirePrivate` 后面，`no-store`，不进日志、`jobs`、`settings`、`seed/`。

## 4. 接口（都在 `/api/expressions` 下）

| 接口 | 作用 |
|---|---|
| `POST /talk` `{ said, thread?, messageId? }` | 一轮。201 `TalkTurn`；`thread` 不存在 404；模型失败 502 `TALK_FAILED` 带 `reason` |
| `GET /talk` | 对话列表，新的在前：`{ threads: [{ thread, title, turns, updatedAt }] }` |
| `GET /talk/:thread` | 一次对话的全部轮次，旧的在前，按现在的遮挡状态出 |
| `DELETE /talk/:thread` | 删除原文和轮次。关联表达的学习记录保留，零命中只保留活动时间。随机消息 ID 用来识别迟到的重发。204 |
| `POST /talk/turn/:id/coach` | 重试该回复的批注；成功回复 `TalkTurn`，不重写回复、不重复命中行 |
| `POST /speech` `{ turn, part? }` | 读取该轮当前遮挡后的回复，返回 MP3；`X-Speech-Parts` 给总段数 |

`POST /talk` 请求带 `Accept: text/event-stream` 时返回 SSE：`delta {text}`、最终 `done {turn}`、失败 `error {error,code,reason?}`。验证和不存在的对话仍在开流前拒绝。`Cache-Control: no-store`、`X-Accel-Buffering: no`，客户端离开时中止上游；回复和批注共享 45 秒，5 秒内暂态失败可重试一次，已有 delta 后不重试，配额、认证和格式错误不重试。

`POST /find` 删除，它的逻辑并进 `POST /talk`。单个英文词有词卡时直接给词卡链接的那条路一并删掉（那是「私人文本进查询串」的唯一例外，随之消失）。

`TalkTurn`：原字段加可选 `coachingFailure`、`review {id,scene}` 和 `reviewResult`（既有 `AttemptResponse`）。回看旧对话时，回顾答案与命中条目里的其它遮挡目标也统一遮住。

消息上限 4000 字符（`EXPRESSION_LIMITS.said`，取代 `need: 1000`）。需求变成提示句时截到 1000。

## 5. prompt

网页用 `REPLY_PROMPT` 生成对谈回复，再用 `COACH_PROMPT` 给已保存的回复做批注。普通 JSON 请求由 `TALK_PROMPT` 一次完成这两步。三份提示词沿用用户给的六条原则（只说英文、地道、认真对话、表达指导、不降低思想深度、不是翻译）。原文在 `src/server/services/conversation-prompts.ts`，管理员也可在设置页查看。

- `reply` 直接回应用户，包括主动提出的用词、语法或语气问题。聊天中顺带发现的措辞问题放到学习反馈。
- `fix`：一个表达清晰的英语使用者会怎么说这句话；用户的英文已经自然就是 `null`。
- `rewrites` 引用原话，每轮至多三条。整句改写和局部修正的理由用一句话说明下次如何判断词义、搭配、语法或语气。
- `fresh`：值得留下的表达，从回复或 `fix` 里逐字取。
- `mine`：库里说得上这句话的条目。
- `scene` 默认为 `null`。有复习线索、回复里确实提出了具体情境、而且用目标表达的意思能自然作答时，才逐字摘录这段邀请。

理由一律用英文，除非用户明说要中文解释。原来「找」的 prompt 已删除；对谈增加回复和批注两阶段，prompt 字符串预算随用户要求的流式方案偏离，不再声称仍是四个。

## 6. 页面

`/talk`，导航里叫「对谈」，只对管理员显示。上面是对话（旧的在上），下面是输入框：回车发送，Shift+回车换行，输入法选字时的回车不发送。每一轮：我说的、对方的回复，回复下面是纠正、值得留下的、库里相关的。能切换和删除旧对话。

这一轮的响应只留在页面的状态里；离开页面再回来，从服务端按当时的遮挡状态重新读。当前开着哪一次对话记在内存里（不进浏览器存储），刷新后回到最新的一次。

表达页的输入框只剩「收下」和「帮我挑」。

每条完整回复前的工具栏有「听语音」和「查看学习反馈」，只有点击朗读才请求 Rime；准备、播放都可以停止。先在点击内激活 Web Audio，再请求和解码 MP3，长回复按句分段到每段不超过 1000 字。切换、卸载、另一条开始朗读时中止上一条。密钥只在服务端 `settings.rime_api_key`，读取时仍为掩码；Coda/Mist、Astra/Luna、倍速在 Providers 页设置。无需 `blob:`，CSP 保持原限制。
